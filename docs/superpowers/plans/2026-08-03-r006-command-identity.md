# R006 and Stats Command Identity Migration Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Generate high-confidence R006 findings and chronic-command stats only from exact CWD/argv/executor identities.

**Architecture:** Aggregate known schema 1 command costs by `commandIdentityKey` once per analysis, ignoring legacy identity-less costs instead of guessing repository root. Match finding session refs by the same exact identity, then derive human-readable targets, recipes, stable finding keys, and stats from the retained identity. Keep legacy records readable but unable to add cost, presence, or evidence to a known identity.

**Tech Stack:** TypeScript 5.9, Node.js 20 test runner, existing schema 1 JSON history

## Edge cases fixed before implementation

- API and Web costs with identical command text never share cost, presence, refs, target, or finding key.
- Shell and native-tool execution of the same CWD/argv remain separate; native display ends in ` [native-tool]`.
- argv order, duplicates, and empty non-leading arguments participate in identity and survive evidence/stats copying.
- Identity-less legacy costs alone never create a high-confidence R006 finding.
- Legacy costs with the same command text cannot raise a known identity's cost or presence count.
- Legacy finding refs and malformed/mismatched finding identities cannot add session refs to a known identity.
- Exact-identity finding refs are included even when their display command differs; command text is never a matching key.
- Duplicate exact-identity costs inside one analysis sum cost but increment presence only once.
- Invalid/non-positive costs and opaque/empty display commands remain excluded.
- Histories without known command costs still contribute only to total history size and measured-time denominator, which can dilute but never strengthen a known cost ratio.
- The normalized command selected for display/verify is the code-unit-smallest valid command observed for that identity, independent of input order.
- Reversing analyses and per-record costs yields identical findings, keys, evidence, and stats ordering, including non-associative floating-point totals.
- Old command-only dismissal keys intentionally do not match new identity-derived R006 keys; no migration occurs.
- Existing manually constructed stats entries without structured identity remain renderable; entries generated by `summarizeStats` always include copied identity while retaining normalized command text in the existing `command` field.
