# ccprof 0.2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 効果追跡（採用検出＋stats 拡張）、Codex セッションソース（capability 宣言つき）、hooks 連携（実時刻記録＋自動実行）、README ポジション明文化を 4 本の PR として順次完成・マージし、0.2.0 の publish 直前まで到達する。

**Architecture:** 既存の決定的パイプライン（sources → timeline → rules → ledger → store → reporters）に対し、(A) store に adoptions を追加して analyze 後段で採用検出を回す、(B) `SessionSource` の第二実装として Codex rollout パーサーを追加し `Session.capabilities` でルール適用可否を制御、(C) 新サブコマンド `hooks` / `hook-event` で Claude Code hooks と接続する。すべて追加のみで JSON v2 後方互換を維持。

**Tech Stack:** TypeScript (Node 20+, ESM, ランタイム依存ゼロ), node:test。ビルドは `npm run build`、検証は `npm test` / `npm run typecheck` / `npm run check`。

## Global Constraints

- spec: `docs/superpowers/specs/2026-08-02-ccprof-0.2-design.md`（承認済み）
- ランタイム依存の追加禁止。外部プロセスは `git`（および PR 解決時の `gh`）のみ

```ts
export function findingFingerprint(finding: Pick<Finding, "scope" | "rule_id" | "fix_recipe"> & { target?: string }): string;
// sha256(`${scope}\0${rule_id}\0${target ?? ""}\0${normalizedSuggestion}`) の hex

export function suggestionKeywords(suggestion: string): string[];
// NFC 正規化 → 小文字化 → /[^\p{L}\p{N}_./-]+/u で分割 → 長さ4以上 → unique → sort → 先頭8個

export interface AdoptionCandidateFinding {
  finding_key: string; rule_id: RuleId; scope: Scope;
  target?: string; suggestion: string; recorded_at_ms: number;
}
export type AdoptionDetectability = "claude_md" | "target_file" | "undetectable";
export function detectability(finding: Pick<AdoptionCandidateFinding, "scope" | "rule_id" | "target">): AdoptionDetectability;
// scope === "claude_md" → "claude_md"
// (rule_id === "R008" || scope === "separate_issue") かつ target がリポジトリ相対パスとして解決可能 → "target_file"
// それ以外 → "undetectable"

export interface DetectAdoptionsOptions {
  repoRoot: string;
  candidates: readonly AdoptionCandidateFinding[]; // 既採用分は呼び出し側で除外済み
  runner?: CommandRunner;
}
export interface DetectAdoptionsResult { adoptions: AdoptionRecord[]; warnings: AnalyzeWarning[]; }
export async function detectAdoptions(options: DetectAdoptionsOptions): Promise<DetectAdoptionsResult>;
```

**検出ロジック（決定的・git のみ入力）:**
- `claude_md`: `git --no-pager log --format=%H%x00%ct -p --unified=0 -- CLAUDE.md` を 1 回実行し、各コミットについて (a) コミット時刻(秒)×1000 > `recorded_at_ms`、(b) `+` 追加行（`+++` 除く）の NFC 小文字化テキストに `suggestionKeywords(suggestion)` のいずれかが部分一致、の両方を満たせば採用。evidence は最初に一致したコミットと `"CLAUDE.md"`。
- `target_file`: target を `normalizeRepoPath`（`src/analysis/test-map.js`）で正規化し、`git --no-pager log --format=%H%x00%ct -- <target>` で `recorded_at_ms` より後のコミットが 1 つでもあれば採用。evidence は最初のそのコミットと target。
- git 失敗（exit != 0）は warning `adoption_detection_failed` を積んで該当候補をスキップ。throw しない。

- [ ] **Step 1: 失敗するテストを書く** — 最低限: (1) keywords 抽出の決定性、(2) fingerprint の安定性、(3) 一時 git リポジトリで CLAUDE.md にキーワード行を後からコミット→claude_md 採用検出、(4) recorded_at_ms より古いコミットのみ→非検出、(5) target ファイル修正→target_file 採用検出、(6) scope this_pr→undetectable

### Task 7: Codex rollout パーサー

**Files:**
- Create: `src/sources/codex/parser.ts`
- Test: `test/codex-parser.test.ts`、fixture: `test/fixtures/codex/`（実ログを匿名化した最小 rollout JSONL を新規作成）

**入力形式（実ログで確認済み）:** 各行 `{"timestamp": ISO8601, "type": "session_meta"|"turn_context"|"response_item"|"event_msg", "payload": {...}}`
- `session_meta.payload`: `id`/`session_id`, `cwd`, `git: { commit_hash, branch, repository_url }`, `cli_version`
- `response_item.payload.type`: `"message"`（`role`: user/assistant, `content`: 配列 or 文字列）、`"function_call"`（`name`, `arguments`(JSON 文字列), `call_id`）、`"function_call_output"`（`call_id`, `output`）、`"reasoning"`
- `event_msg.payload.type`: `user_message` / `agent_message` / `token_count` / `task_started` / `task_complete`

**Interfaces:**

```ts
export interface ParseCodexSessionOptions { sourcePath: string; raw: string; }
export function parseCodexSession(options: ParseCodexSessionOptions): Session | null;
// 解析可能行ゼロなら null。Session.source = "codex"、
// capabilities = ["tool_timestamps"]、observed_branches = [session_meta.git.branch]
```

**正規化マッピング:**
- `response_item` `message` role=user → `GenuineUserEvent`（content 配列は text 要素を連結。`<user_instructions>` 等のタグ付き injected テキストで始まるものは skip）
- `message` role=assistant → `AssistantEvent`（token 数は付けない）
- `function_call` → `ToolUseEvent`: `tool_use_id = call_id`, `tool_name = name`, `input = JSON.parse(arguments)`（parse 失敗は `{}` + warning）。`name === "exec_command"` または `"shell"` のとき `command = input.cmd ?? input.command 連結`、`cwd = input.workdir`
- `function_call_output` → `ToolResultEvent`: `output` 先頭部の `Process exited with code (\d+)` を exit_code として抽出し、0 → success / それ以外 → failure / 不明 → unknown。`estimated_tokens = ceil(output.length / 4)`、`output_bytes = Buffer.byteLength(output)`
- `reasoning`・`event_msg`・`turn_context` → イベント化しない（`token_count` は将来用に無視）
- `entry_uuid` は `${行番号}` ベースで決定的に生成、`agent_id` は session_id、`is_sidechain = false`、行単位の破損は `SourceWarning` 化（コード `codex_row_invalid`）して継続
