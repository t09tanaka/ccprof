# ccprof 0.2 設計書 — 効果追跡・Codex ソース・hooks 連携

日付: 2026-08-02
ステータス: 承認済み（チャットで設計承認）
対象バージョン: 0.2.0（現行 0.1.1）

## 背景と目的

外部レビューで指摘された 5 点のうち、0.2 では以下の 4 点に対応する。

1. 効果追跡が未完成（採用された提案が効いたかを追えない）
2. （見送り）決定的ルールの検出範囲の天井
3. 対応ソースが Claude Code のみ（Codex パーサー未実装、未知 MCP ツールが unexplained のまま）
4. 計測精度の限界（タイムスタンプがログ書き込み時刻）
5. ループ実行が規約頼み（hook 等のハーネス側強制がない）

テーマ: **「測って、直させて、効いたか確かめる」ループの完結 + マルチハーネス第一歩**。

指摘 2 は 0.2 では対応しない。「ccprof は過程の無駄を測る。判断の正しさは測らない」というポジションを README に明文化し、opt-in の advisory 層を 0.3 候補として記録する。決定的・LLM 不使用は差別化の核であり、0.2 では崩さない。

## 1. 効果追跡（指摘 1）

### 記録

- ledger の finding 記録に「提案フィンガープリント」を追加する。フィンガープリントは finding の `scope`・`rule_id`・`target`・`fix_recipe.suggestion` の正規化から決定的に生成する。
- 次回 `ccprof` 実行時（analyze 経路）に**採用検出器**が走り、過去の未解決 finding それぞれについて採用痕跡を決定的に検査する。検出したら ledger に adoption イベント（finding-key、検出方法、検出根拠、検出日時）を記録する。

### 採用検出器（scope / rule をキーにした決定的ロジック）

| キー | 採用痕跡 |
|---|---|
| scope = `claude_md` | finding 記録以降のコミットで CLAUDE.md に、フィンガープリントのキーワード（suggestion から抽出した正規化トークン）を含む行が追加された |
| rule = R008（flaky-test） | 対象テストファイル（target）が finding 記録以降のコミットで修正された |
| scope = `separate_issue`（上記以外） | target がファイルパスとして解決できる場合のみ、そのファイルが finding 記録以降に修正されたことを痕跡とする |
| 上記以外（scope = `this_pr` 等、痕跡がファイルに残らないもの） | 検出対象外。検出対象外であることを stats 上で明示する |

検出は git 履歴とファイル状態のみを入力とし、同じ入力からは同じ結果を返す。

### 効果測定（因果を主張しない）

- `ccprof stats` に「採用済み提案 → その後の同種 finding の再発率・推定損失分数の推移」セクションを追加する。
- 表示は観察事実に限定する（例: 「採用後 N PR で同種再発なし」）。因果の主張はせず、caveat を明記する。
- JSON v2（stats `--json`）にも同セクションを追加する。既存フィールドは変更しない（後方互換）。

## 2. Codex ソース（指摘 3・段階的対応）

### パーサー

- `src/sources/codex-source.ts` を新設し、`~/.codex/sessions` 配下の JSONL を既存 `Session` モデルに正規化する。
- 発見クエリは既存 `SessionSource` インターフェース（repoRoot / headBranch / 期間）に従う。
- パース失敗は既存方針どおり warning + confidence 低下で劣化し、解析可能なセッションが残る限り落とさない。
- ソース選択: Claude Code セッションと Codex セッションの両方が見つかった場合は両方を解析対象に含める。環境変数 `CCPROF_CODEX_SESSIONS_DIR` で探索先を上書きできる（テスト・特殊レイアウト用、既存の `CCPROF_CLAUDE_PROJECTS_DIR` と同型）。

### capability 宣言

- `Session` にソースが提供できる情報の capability フラグ集合を持たせる（例: `tool-timestamps`、`token-usage`、`sidechains`）。
- 各ルールは必要 capability を宣言する。不足するルールは confidence を下げるのではなく「このソースでは適用外」として理由付きで明示スキップし、レポート（TTY / JSON / MD）にスキップ理由を出す。
- 既存 Claude Code ソースは全 capability を持つものとして扱い、既存挙動は変えない。

### 未知 MCP ツールの分類フォールバック

- コマンド分類器に、`mcp__<server>__<tool>` 形式のサーバー名 prefix に基づくフォールバック分類を追加し、unexplained を削減する。

## 3. hooks 連携（指摘 4 + 5）

### CLI

- `ccprof hooks install [--global]` / `ccprof hooks uninstall [--global]` を新設する。既定はリポジトリの `.claude/settings.json`、`--global` で `~/.claude/settings.json` を対象にし、確認プロンプト付きで hook 設定を追記・削除する。既存設定は保持し、ccprof 由来のエントリのみを冪等に追加・削除する。
- `ccprof hook-event` を新設する。Claude Code hook から呼ばれ、stdin の hook JSON を XDG データディレクトリ配下のイベントログ（JSONL、リポジトリ単位）に追記する。**常に exit 0** とし、いかなる失敗でもセッションを妨げない。処理は軽量（追記のみ）に保つ。

### 実時刻記録（指摘 4）

- Stop hook で セッション終了の実時刻を `hook-event` 経由で記録する。
- タイムライン解析は、イベントログに対応する実時刻がある場合はログ書き込み時刻より優先して使用する。イベントログがない場合は従来どおり（caveat 維持）。

### 自動実行（指摘 5）

- 同じ Stop hook で `ccprof` を自動実行し、findings があれば要約を hook 出力として表示する（通知型）。エージェントを block する強制は行わない。

## 4. README・ポジション明文化（指摘 2 の見送り記録）

- README に「ccprof は過程の無駄を測る。判断の正しさは測らない」を明記する。
- opt-in advisory 層（LLM 支援の助言レイヤー）を 0.3 候補として README の今後の拡張に記録する。
- hooks 導入手順、Codex 対応範囲（適用外ルールの一覧）、効果追跡の caveat を README に追記する。

## PR 分割と順序

1. **PR A: 効果追跡** — ledger 拡張、採用検出器、stats 拡張（本設計書のコミットを含む）
2. **PR B: Codex ソース** — codex-source、capability 宣言、MCP 分類フォールバック
3. **PR C: hooks 連携** — `hooks install/uninstall`、`hook-event`、実時刻優先、Stop hook 自動実行
4. **PR D: README・バージョン 0.2.0 準備** — ポジション明文化、ドキュメント追記

各 PR は独立にマージ可能な単位とし、順次作成・マージする。

## テスト

- 採用検出器: 種別ごとの unit test（git fixture で採用あり/なし/対象外を検証）
- Codex パーサー: fixture JSONL による正規化テスト、capability 由来の適用外スキップの検証
- hook-event: 不正入力・書き込み失敗でも exit 0 を返す統合テスト、イベントログ追記の検証
- stats: adoption セクションの JSON 後方互換テスト

## エラー処理

既存方針を踏襲する: warning + confidence 低下で劣化し、解析を落とさない。`hook-event` のみ「常に exit 0」の特則を置く。

## 互換性

- JSON v2 スキーマは追加のみ（破壊的変更なし）。
- 既存の exit code・CLI 引数は変更しない。新サブコマンド（`hooks`、`hook-event`）の追加のみ。
